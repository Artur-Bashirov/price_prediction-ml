# Price Direction Classifier (LightGBM) — Model Card

Model Cards предназначены для предоставления важной информации о моделях машинного обучения, включая известные ограничения, подходы к оценке и рекомендации по безопасному использованию.

**Опубликовано:** Октябрь 2026 г.

## Информация о модели (Model Information)

### Description (Описание)
**Price Direction Classifier** — это модель бинарной классификации, предназначенная для прогнозирования направления движения цены финансового актива на следующий торговый день (Up / Down) на основе исторических данных OHLCV и технических индикаторов. Модель обучена на дневных котировках за период 2014–2024 гг. и демонстрирует статистически значимое превосходство над базовой линией (Dummy Classifier) по метрикам Accuracy и ROC-AUC.

### Model dependencies (Зависимости модели)
- **LightGBM** — градиентный бустинг на деревьях решений (histogram-based)
- **Scikit-learn** — Pipeline, ColumnTransformer, StandardScaler, TimeSeriesSplit
- **statsmodels** — ADF-тест стационарности
- **pandas, numpy, matplotlib, seaborn, joblib**

### Inputs (Входные данные)
Исторические дневные котировки в формате OHLCV:

| Признак | Тип | Описание |
|---------|-----|----------|
| `date` | datetime | Торговая дата |
| `open` | float | Цена открытия |
| `high` | float | Максимальная цена |
| `low` | float | Минимальная цена |
| `close` | float | Цена закрытия |
| `vol` | int | Объём торгов |

На основе сырых данных пайплайн автоматически конструирует **31 признак**:
- **Лаги цен и объёма**: `close_lag1/2/3`, `vol_lag1`
- **Доходности**: `return_1d`, `return_lag_2`, `return_lag_3`, `return_intraday`
- **Трендовые (SMA)**: `price_to_sma5`, `price_to_sma20`
- **Волатильность**: `volatility_5`, `volatility_20`, `hl_range`
- **Объёмные**: `vol_sma5`, `vol_ratio`
- **Технические**: `rsi_14`
- **Циклические (sin/cos)**: `weekday_sin/cos`, `month_sin/cos`, `day_of_year`

### Outputs (Выходные данные)
- **Класс**: `0` (Down — падение) или `1` (Up — рост)
- **Вероятности**: `predict_proba()` возвращает распределение `[P(Down), P(Up)]`

### Architecture (Архитектура)
Модель реализована как `sklearn.Pipeline` из двух шагов:

1. **ColumnTransformer** (preprocessor):
   - `StandardScaler` — для 27 числовых признаков
   - `passthrough` — для 4 циклических признаков (sin/cos уже нормализованы в [-1, 1])
2. **LGBMClassifier** с параметрами:
   - `n_estimators=300`, `learning_rate=0.05`, `max_depth=5`
   - `num_leaves=31`, `subsample=0.8`, `colsample_bytree=0.8`
   - `reg_alpha=0.1`, `reg_lambda=0.1`, `tree_method='hist'`

## Данные модели (Model Data)

### Training Dataset (Обучающий набор данных)
| Параметр | Значение |
|----------|----------|
| **Источник** | `test_ds_1.xlsx` (исторические котировки) |
| **Исходный объём** | 2507 записей |
| **Период** | 16 июня 2014 — 14 июня 2024 |
| **После Feature Engineering** | 2457 записей |
| **Целевая переменная** | `target`: 0 (Down) / 1 (Up) |
| **Баланс классов** | Up: 51.3%, Down: 48.7% |

### Training Data Processing (Обработка обучающих данных)
1. **Хронологическая сортировка** по дате (не по индексу) — для сохранения временного порядка.
2. **Feature Engineering** с правилом *shift → rolling*: все лаги и скользящие окна считаются от сдвинутых значений, что исключает look-ahead bias.
3. **Проверка стационарности** (ADF-тест): ряд `return_1d` стационарен (ADF = -49.74, p-value = 0.000000).
4. **Хронологическое разделение** 80/20 по квантилю даты:
   - Train: 1965 записей (2014-08-25 → 2022-07-07)
   - Test: 492 записей (2022-07-08 → 2024-06-14)
   - Пересечений между выборками нет (assert-проверка).
5. **Винзоризация** (1-й и 99-й перцентили) рассчитана **строго на train** и применена к обеим выборкам — предотвращает утечку данных.
6. **Удаление NaN**, возникших после расчёта лагов и скользящих окон.

### Hardware (Оборудование)
Обучение и инференс оптимизированы для **CPU**. Использование `tree_method='hist'` в LightGBM значительно снижает требования к памяти и вычислительной мощности по сравнению с точным алгоритмом.

### Distribution (Распространение)
Модель сохраняется в виде трёх артефактов:
- `best_model.pkl` — обученный пайплайн (preprocessor + классификатор)

Для развёртывания не требуется специфическое оборудование — достаточно среды выполнения Python с указанными зависимостями. Инференс выполняется на одной новой строке с биржи (OHLCV за завершённый торговый день).

## Оценка (Evaluation)

### Approach (Методология)
Оценка проводилась с учётом специфики временны́х рядов:

1. **TimeSeriesSplit (5 folds)** — вместо стандартного K-Fold, чтобы исключить заглядывание в будущее.
2. **Dummy-базовая линия** (`DummyClassifier(strategy='stratified')`) — контроль адекватности: модель должна статистически значимо превосходить случайное угадывание.
3. **Хронологический hold-out** — тестовая выборка (2022–2024) не участвовала ни в обучении, ни в подборе гиперпараметров.
4. **ADF-тест** — подтверждение стационарности признаков-доходностей.
5. **Винзоризация только на train** — защита от утечки статистики выбросов.

## Предполагаемое использование и ограничения (Intended Usage and Limitations)

### Benefit and Intended Usage (Преимущества и предполагаемое использование)
Модель хорошо подходит для:
- Создания базовых сигналов в алгоритмических торговых стратегиях.
- Оценки краткосрочного рыночного настроения на основе чисто технических факторов.
- Использования в качестве одного из признаков (meta-feature) в более сложных ансамблевых моделях.

### Known Limitations (Известные ограничения)
- **Потолок точности**: Accuracy ~56% является реалистичной для дневных таймфреймов эффективного рынка, но недостаточной для гарантированного извлечения прибыли без строгого риск-менеджмента.
- **Отсутствие фундаментальных данных**: Модель опирается исключительно на цену и объём, игнорируя макроэкономические новости, отчёты компаний или геополитические события.
- **Смещение предсказаний**: Модель чаще предсказывает класс 'Down'. При использовании без пороговой фильтрации это может привести к избыточному количеству ложных срабатываний на классе 'Up'.
- **Концептуальный дрейф (Concept Drift)**: Паттерны, выученные на данных 2014-2024 гг., могут устареть при смене рыночного режима.

## Допустимое использование (Acceptable Usage)

- Использование в исследовательских и образовательных целях.
- Интеграция в торговые системы **только** в сочетании со строгими правилами управления капиталом (stop-loss, position sizing).
- Использование в качестве фильтра для отсеивания заведомо плохих сделок, а не как единственный источник истины для входа в позицию.

**Запрещённое использование**:
- Использование модели для высокочастотного трейдинга (HFT), для которого она не предназначена (дневной таймфрейм).
- Принятие крупных финансовых решений исключительно на основе предсказаний этой модели без человеческого контроля.

## Этика и безопасность (Ethics and Content Safety)

### Evaluation Approach (Подход к оценке)
Основной этический риск финансовых ML-моделей заключается в создании у пользователей ложного чувства уверенности ('иллюзия предсказания'), что может привести к финансовым потерям. Оценка фокусировалась на честном сравнении с базовой линией и использовании строгой временной валидации, чтобы не завышать реальные возможности модели.

### Safety Policies (Политики безопасности)
- Модель не использует и не собирает персональные данные (PII).
- В документации явно указаны метрики производительности (Accuracy ~56%), чтобы предотвратить нереалистичные ожидания пользователей относительно 'гарантированной прибыли'.

### Financial Validation & Expert Review (Финансовая валидация и экспертная проверка)
Вместо традиционного 'Red Teaming' для финансовых моделей применяется финансовая валидация:
- **Walk-Forward оптимизация**: Тестирование модели на скользящих окнах для симуляции реального развёртывания.
- **Ручная проверка 'серой зоны'**: Случаи с низкой уверенностью модели (вероятность близка к 0.5) принудительно передаются на ручную проверку трейдером, что исключает риск автоматической ошибки в неоднозначных ситуациях.

## Риски и меры по их снижению (Risks and Mitigations)

### Risks (Риски)
- **Финансовые потери**: Из-за того, что точность модели лишь немного превышает 50%, слепое следование её сигналам приведёт к убыткам на дистанции из-за комиссий и проскальзывания.
- **Переобучение на исторических данных**: Модель может выучить шум, специфичный для определённого исторического периода.
- **Концептуальный дрейф**: Резкие изменения рыночной волатильности могут сделать выученные веса признаков устаревшими.

### Mitigations (Меры по снижению)
1. **Пороговое прогнозирование (Probability Thresholding)**: Вместо использования жёсткого порога 0.5, рекомендуется открывать позиции только тогда, когда уверенность модели (`predict_proba`) превышает 60-65%. Это повысит Precision за счёт уменьшения количества сигналов.
2. **Ансамблирование**: Комбинирование предсказаний LightGBM с RandomForest или другими алгоритмами для сглаживания ошибок.
3. **Смена постановки задачи**: Если бинарная классификация достигает потолка, рекомендуется перейти к регрессии квантилей (Quantile Regression) для оценки потенциального диапазона движения цены, а не просто её направления.
4. **Регулярное переобучение**: Внедрение пайплайна автоматического переобучения модели на скользящем окне (rolling window) последних данных для адаптации к текущему рыночному режиму.
